# Lineae 长期实现大纲

目标是让数学编辑接近 Mogan，日常文稿编辑接近 Pages 和 Word，并逐步扩大真实 TeX 项目的兼容范围。以源码保真、可预测的编辑行为和可复现的验收为发布门槛。

## 当前基线

以提交 `8dcdbe8` 的实现为基线。已具备富文本、公式编辑、源码模式、打开和保存、基本结构与引用、纸面标题和作者、双语界面及部分数学环境。相关实现见 [应用入口](../apps/web/src/main.js)、[导入导出](../apps/web/src/editor/latex-codec.js) 和 [编辑器架构](EDITOR_ARCHITECTURE.md)。本次本地源码与 UI 测试 50 项通过。浏览器回归和线上部署沿用交接报告，本次未重新验证。

## 主线排期

以下排期由项目当前风险决定，优先于下方原始功能清单的优先级。每阶段交付一组可复验的功能，不以命令数量衡量进度。

| 顺序 | 交付 | 验收门槛 |
| --- | --- | --- |
| 1 | 公式渲染和正文命令。为正文符号建立单一命令表，区分标准的 `\LaTeX`、`\TeX`、`\textasciitilde`、`\textasciicircum` 与未知命令。公式按行内、行间、矩阵、多行对齐逐组核对。 | 插入、导入、显示、编辑、导出分别测试。编辑周围文字后，符号命令和公式边界仍可往返。未知语法保留源码。 |
| 2 | 源码保真与历史。引入源码范围和局部写回，统一模式切换、撤销和保存点。 | 无编辑切换不产生事务，局部编辑只改目标区域，失败可恢复原文。 |
| 3 | Mogan 核心交互。集中攻克占位选区、矩阵单元格、分数和上下标导航、公式进出正文。 | 键盘和鼠标可完成相同编辑，跨结构撤销和粘贴保留内容。 |
| 4 | Pages / Word 基础体验。完善标题、列表、表格、查找替换、格式工具、输入法与保存恢复。 | 跑通长文稿的输入、改样式、重排、查找、保存和重新打开。 |
| 5 | 项目与出版。多文件依赖、资源、文献、编译诊断和 PDF 同步。 | 编译基于固定源码修订，错误可定位，预览能识别过期结果。 |

第一阶段将交互预览与真实 TeX 输出分别验收。公式浏览器回归覆盖字体、上下标、分数、根式、矩阵及 AMS 环境，真实编译基准用于发现排版差异。先针对现有 MathLive 路径验证差异，再决定是否增加只读渲染层。参考 R9、R10、S3。

桌面封装、精确分页和审阅协作移出基础版交付。资料核对和 UI 组件可并行分派，核心源码模型、公式事务和渲染适配集中维护。附录条目若重叠，以本表的交付和验收条件为准。

建议的开发顺序
建议先完成 结构化文档模型、源码范围映射、局部写回、未知源码块和跨模式编辑历史。这几项决定编辑器能不能安全修改真实 LaTeX 文件。随后再完善正文、标题、列表、表格和数学环境的有限支持范围，并为每种结构补齐导入、编辑、导出和异常回退规则。文件会话、搜索导航和自动恢复可以在数据模型稳定后推进；多文件、编译和 PDF 工作流则放在后续阶段。

### 建议的编辑体验验收顺序
先验收 光标和选区、中文输入法、格式工具、撤销重做、公式进出和保存状态。这些是每次编辑都会触及的基础交互。然后验收列表、表格、剪贴板和长文导航，最后处理工具栏布局、可访问性和偏好设置。

每项功能至少要检查四种情况：光标在普通正文中、光标处于已有格式区域、选区跨越不同结构、操作后立即撤销并重做。公式、表格和中文输入法还需要单独检查键盘操作，因为它们最容易暴露光标、焦点和编辑历史不一致的问题。
